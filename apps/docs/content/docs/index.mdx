# Welcome to LotOS UI

LotOS UI is built to keep **design quality** and **functional quality** aligned while teams work with AI agents.

The core idea is simple:

1. **Design contract**: tokens + pattern blueprints define hierarchy, spacing, and interaction intent.
2. **Functional contract**: schemas + framework-aware snippets keep generated code valid.
3. **Runtime clarity**: every ecosystem has a visible status so roadmap and production are not mixed.

## Current reality

| Capability | Status |
|---|---|
| React component arm (`@lotosui/claude-arm`) | Stable |
| MCP server endpoints (`/components`, `/runtimes`, `/patterns`) | Stable |

| Laravel Blade adapter track (`lotos-laravel`) | Alpha |

## Package map

```
@lotosui/core          - Tokens, schemas, runtime catalog, design patterns, MCP server
@lotosui/claude-arm    - React component arm (production)
@lotosui/web-components- Web component prototypes
@lotosui/sentinel      - Runtime warnings and misuse guardrails
@lotosui/cli           - Project commands and runtime/pattern discovery
```

## System architecture

1. Core contracts (`@lotosui/core`): tokens, schema rules, runtime catalog, pattern blueprints, stack templates.
2. UI execution arms:
- React production arm (`@lotosui/claude-arm`)
- Cross-framework web components (`@lotosui/web-components`)
3. Intelligence/control plane:
- MCP endpoints for agents (`/components`, `/runtimes`, `/patterns`, `/desktop/templates`, `/stacks`)
- Sentinel warnings (`@lotosui/sentinel`)
4. Delivery tooling (`@lotosui/cli`):
- `blueprint` for runtime + pattern contracts
- `desktop-init` for Python/Rust/Java/C/C++ desktop shells
- `stack-init` for PHP/Python/Java/.NET/Go + Mongo capable starters

## What teams can do right now

1. Start a production React UI with schema-safe components.
2. Generate cross-language starter stacks with one CLI command.
3. Build desktop shells with rich visual templates and bridge contracts.
4. Keep AI-generated output aligned to design and implementation contracts via MCP.
