# Welcome to LotOS UI

LotOS UI is built to keep **design quality** and **functional quality** aligned while teams work with AI agents.

The core idea is simple:

1. **Design contract**: tokens + pattern blueprints define hierarchy, spacing, and interaction intent.
2. **Functional contract**: schemas + framework-aware snippets keep generated code valid.
3. **Runtime clarity**: every ecosystem has a visible status so roadmap and production are not mixed.

## Current reality

| Capability | Status |
|---|---|
| React component arm (`@lotosui/claude-arm`) | Stable |
| MCP server endpoints (`/components`, `/runtimes`, `/patterns`) | Stable |
| Web Components package (`@lotosui/web-components`) | Prototype |
| Laravel Blade adapter track (`lotos-laravel`) | Alpha |
| Django, Flask, Spring, .NET, Go, C/C++, Mojo adapter tracks | Planned / in blueprint phase |

## What makes LotOS different

| Feature | LotOS UI |
|---|---|
| Runtime status by ecosystem | Yes |
| Shared design patterns across runtimes | Yes |
| Schema-driven component contracts | Yes |
| MCP endpoints for agent consumption | Yes |
| Sentinel misuse warnings | Yes |

## Package map

```
@lotosui/core          - Tokens, schemas, runtime catalog, design patterns, MCP server
@lotosui/claude-arm    - React component arm (production)
@lotosui/web-components- Web component prototypes
@lotosui/sentinel      - Runtime warnings and misuse guardrails
@lotosui/cli           - Project commands and runtime/pattern discovery
```
